One service. Three execution paths.

Measured feasibility trials across incident recovery and a broader holds/invoice change. Same task materials and acceptance per case; GPT-6.1 Sol throughout.

Six attempts · one harness · one run per task/approach

API-equivalent costs are counterfactual token estimates, not subscription charges or quota. A real API run may have different cache hits or service-tier behavior. These are controlled service-core tasks, not a production-scale workload or a general ranking.

Observed here: single sessions were fastest and cheapest and passed every functional group. The holds/invoice single session passed full acceptance; the incident run has the artifact-format caveat below. Parallel orchestration finished sooner than sequential orchestration on both tasks, but was cheaper only on the incident task. Different call graphs and recovery work contribute to these results.

Read functional quality separately from artifact compliance.

Full acceptance also requires unchanged context, structured evidence artifacts and added-test checks. In the first single-session incident run, the required facts were present as ID-bearing objects; the frozen scorer expected strings. Its public shorthand schema did not explicitly type those members. The recorded failure is preserved, but it is not a functional defect or evidence of missing reasoning. No rubric was changed after launch.

What each run received

50 initial files · 31 source/test modules · 15 context nodes · about 40 KB. The fixture has meaningful module boundaries but is smaller than the design's aspirational line-count target. No filler was added.

Service repository

Orders, durable journal, fulfillment, authorization, billing, audit and thin API adapters. Existing regressions are frozen.

Internal-style context

Current contracts and requirements, incident timeline/log, security policy, operational notes and superseded decisions with explicit authority.

External-style context

Frozen delivery-idempotency and integer-money references. Supplied locally; no live MCP endpoint, network lookup or external service is required.

Measurement boundaries

  • Same business prompt, source bytes and acceptance within each task; execution wrappers and managed protocol overhead differ intentionally.
  • Thirty-minute/300-request bounds per attempt, maximum two workers. B/C use the same capacity setting; B is serial, C may overlap research and validation. Implementation stays exclusive.
  • Order: incident A/B/C, then feature B/C/A. One trial per condition, natural caching and shared host/provider load. Call graphs differ: retries and generated work also affect timing and cost. This is not an isolated speedup test of the same call graph, and supports no significance or general superiority claim.
  • Cumulative input sums repeated context across calls; peak input is the largest single request. Exact initial prompts, common constraints, installed protocols, evaluator bundle and gate results are inspectable. Complete provider/system prompts and all assembled contexts were not retained.
  • Mechanical artifact scoring checks anchors and paths; it cannot grade all prose or establish every self-reported command. Native same-user access is not adversarial evaluator isolation.
  • API-equivalent estimates use the frozen 5 November price snapshot, count reasoning once, and exclude tool/infrastructure charges and subscription quota. Request usage is reconciled with native records; any gaps remain explicit. Request overlap measures simultaneous in-flight requests, not provider-internal GPU scheduling.
  • These results are specific to the tested OpenCode configuration. The task repositories and evaluator are reusable across harnesses; numerical extrapolation requires replication.

Rates frozen 5 November 2026 from the model specification and API pricing: $2 / $0.10 / $2.50 / $10 per million uncached input / cache-read / cache-write / output tokens. Above 272,000 input tokens, full-request rates are $4 / $0.20 / $5 / $15.
