# Route scoped work by difficulty

## Use when

Bounded evidence work may suit a smaller model while difficult decisions stay with the coordinator.

## Inputs and prerequisites

Scoped task, acceptance contract, available models and a baseline cost/quality record.

Delivered mechanism: **Native agent definitions / protocol**. Native integrations are selected per harness; portable guidance does not imply automatic native enforcement.

## Procedure

1. Use the delivered read-only Claude CI-evidence and fixture-review definitions when appropriate; verify native availability before depending on aliases.
2. Start with bounded extraction/review tasks whose outputs can be checked. Escalate ambiguity, contradictions and weak reports to the coordinator or a more capable model.
3. Validate and reconcile worker returns before they influence edits/acceptance. Keep separate input/output schema at each stage.
4. Compare all-call cost, cache partitions, outputs and overhead per accepted task. Do not assume a cheaper per-token rate is a cheaper successful workflow.

## Output contract

An explicit routing decision and scoped report; other harnesses receive a portable routing protocol in this bundle.

## Verification and evaluation

Trial representative simple and difficult subtasks on the actual selected models. Record failures and worker overhead, not only successful savings candidates.

## Limits and recovery

The installer does not automatically route every task or provide unsupported native agent configuration. Repricing synthetic usage in the presentation does not measure model quality or actual hit rates. Preserve existing unrelated files/hooks and enterprise settings. If a managed file differs, review it rather than overwriting. Keep task evidence until the project's retention/acceptance requirements permit removal.
